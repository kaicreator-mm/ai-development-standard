## 1. Product value and non-negotiable outcomes
v4.17 strengthens **source-qualified Agent engineering reliability, process evaluation, bounded recovery, evidence-based evolution and interoperable public feedback**, without turning ADS into a runtime or duplicating existing standards. At the end, a project can (a) prove first-divergence/correct owner, (b) exercise legal positive ACT and safe refusal ABSTAIN, (c) verify cumulative evolving requirements with independent oracles, (d) resolve stale memories and multi-Agent conflicts, (e) compare optional Harness/Skill changes without leaking evaluators, (f) produce source-qualified behavior/evidence→decision→effect→feedback claims, (g) handle source corrections and changed eligibility, and (h) test GitHub-only task-meta/Tally consumer compatibility.

ADS defines only standard semantics + language-neutral Golden/forbidden conformance. It does **not** implement task-meta private source capture, Tally Agent registry/policies/strategy selection, DomainHarness Kernel or external provider/Host effects.

## 3. Mandatory contract invariants
- **Single engineering truth:** GitHub native Task/Dependencies/PR/CI/Review/accepted Claim and actual Host own their real facts; Report/Task Learning and Tally projections cannot mint Task/Review/Validation/Release PASS.
- **Source identity:** Pin effective immutable ADS revision/profile, subject SHA/Task/Attempt, observer/report source, native GitHub ID, integrity/currentness, actor role/session distinct from transport login; never infer missing identity from timestamps or model brand.
- **Epistemic evidence:** OBSERVED, SELF_REPORTED, INFERRED, UNKNOWN kept separate with capture coverage; UNKNOWN is not zero, absent a complete page is not proof of absent Task, and a successful CI job is not general Release PASS.
- **Correction/invalidation:** Preserve original immutable record; allowed corrections/late revisions apply per original owner and compatible wire; derived eligibility re-evaluation never edits historical Effect or secretly hot-swaps live Package.
- **Evolution:** Task Learning/telemetry are inputs only; Product Evidence→PRD→L2→Task DAG→Validation→Review→Release still required for normative changes.
- **Isolation:** No mandatory new gate/judge/scorer, agent optimizer, skill generator, backend, Tally direct task-meta API/DB/manifest/Trace, provider-specific hook, raw chain-of-thought/prompt publication, or private grader disclosure.
- **Compatibility:** Keep v3/v4/v5 historical schema bytes untouched; only future separately approved public wire/projection if actual bounded semantic gap proven. v5 opt-in requires lawful qualified current adoption; old-reader UNSUPPORTED is expected.
- **Proportionality:** Optional simulations/quality/process warnings do not block a legitimate simple Task or weaken required validation. Reuse source-unchanged local tests and justify extra Host/CI by impact.

## 4. Key user journeys and falsifiable cases
**J1 Normal success / legal ACT:** Project uses current frozen Task+ADS pin, permitted Tool capability and Claim; independent evidence proves actual operation and applicable Gate. A diagnostic suggesting inefficiency must not turn true PASS into FAIL. Evidence/feedback distinguishes recommendation, application and independent effect.

**J2 Safe failure / denial / recovery:** expired Claim or wrong write scope refuses effect; benign 503 after unknown ACK is reconciled with source receipts, never blindly repeated. Root fault belongs to external Environment vs Product/Agent as actually evidenced, not automatic blame.

**J3 Long-lived multi-Agent evolving spec:** new feature must preserve old applicable safety contract and current ABI; two separate file writers can conflict on logical Contract despite disjoint file paths. Old Reviewer PASS and stale retrieved memory cannot qualify new SHA.

**J4 Experiment and TraceML:** development-held-out split + reproducible source/state/time basis; a candidate appearing better due to hidden oracle leak or double-counted Pivot fails. Valid opportunity denominator and negative cases preserve uncertainty.

**J5 Task-meta→GitHub→Tally→GitHub:** task-meta emits bounded factual source report; Tally C GitHub reads native summary (no manifest dereference), decides optionally, K/Host executes with legal authority, Tally publishes safe feedback. Duplicate report/correction/partial pages and wrong verifier do not falsely promote Candidate. Real E2E #1210/#1231 separately NOT_RUN, source-only Golden cannot substitute.

### P1-01 / FR08 — Version/Transition/Pivot/Revisit exact acceptance
- An observed `VersionState` MUST retain source-qualified immutable artifact/strategy identity, governing owner and scope. `Transition` MUST have native/causal lineage and stable deduplicated operation reference; chronology inferred from wall clock or Git diff is invalid.
- `Pivot` requires a **witnessed change of governed goal/strategy** across an eligible source-qualified Transition, not merely a code revision. `Revisit` requires a witnessed earlier departure and an independently established A′ strategy/goal *equivalence* to the earlier A under compatible scope, not matching bytes or narrative similarity; A′ may be a different SHA.
- Numerator and denominator are distinct: `N_pivot / D_pivot` among witnessed comparable Transition opportunities whose before/after strategy refs are resolved; `N_revisit / D_revisit` among witnessed comparable opportunities with known prior strategy departure and qualified equivalence eligibility. Duplicate events count once; missing intermediate, parallel nonordered lineage, incomplete capture, ambiguous goal/currentness, wrong SHA or conflict contribute to **neither** numerator nor denominator and are reported as UNKNOWN/opportunity-coverage loss, not automatically a negative observation. Denominator 0 ⇒ NOT_COMPARABLE/INSUFFICIENT_EVIDENCE.
- **Positive** observed A(goal-X, sha A)→B(goal-Y, sha B)→A′(goal-X, sha C, owner-equivalent) = Pivot 2 of 2 qualified change opportunities; Revisit 1 of 1 qualified post-departure return opportunity, if all source checks succeed. **Negative** source edit but governed strategy unchanged = Pivot 0 of 1; code rollback/duplicate replay/partial parallel histories without owner decision cannot establish a Revisit or silently fill a denominator.
- No new `ads/github/v5` fields, required Agent tracer, mandatory Task-wide Pivot rate, model-estimated intent, or causal superiority claim follows.

### P1-02 / FR10 — consumer-material dependency invalidation boundary
- A derived **material** recommendation/eligibility use must be traceable to the *actual consumed public report/native source claims* and their qualified identity/revision/currentness. Recheck at each **new material context/selection/candidate qualification or promotion** boundary and before later authorized new K/Host effects, not retroactively rewriting historical occurrences.
- `VERIFIED_CURRENT` source stays usable within its actual qualification, not automatically Task PASS. `VERIFIED_REVOKED_OR_STALE` which negates a material consumed premise => no new dependent selection/promotion until requalification. `UNVERIFIABLE_OR_PARTIAL` => fail-closed UNKNOWN on *new* dependent use. `FOREIGN_DISPUTED` => notice alone does not revoke, but actual material unresolved currentness conflict cannot be treated as verified.
- Corrected material evidence does not invalidate an independently supported, unrelated premise. Historic Report revisions/Task status, previously authorized BUILD pins and actual Effect receipts remain unchanged. Only existing Tally/DomainHarness owner can effect requalification, new selection or lawful rollback; ADS does not mint a Candidate state/Gate or push bus.
- **Positive** verified revoked only source supporting P blocks *future* P adoption, while old running P BUILD remains as was; **negative** foreign-namespace claim must not cancel source, partial GitHub result cannot be treated as clean/empty, unrelated Q metric correction must not automatically veto independently qualified P. Verified replacement evidence requires ordinary new qualification.

### R2-P1-A: C08 usable source/epistemic lanes (Product acceptance)
- **Strict OBSERVED lane**: an already-authoritative accepted goal/strategy decision is publicly and causally linked to source-qualified `VersionState`/Transition via frozen Product/Task/Issue/PRD/procedure/approved owner reference. Optional logical `StrategyCandidateRef` points to *that existing owning ref*; it does not create a v5 wire key or permission. A′ may have different code SHA but requires independent owner-backed strategy equivalence under same scope. Existing R1 `N_obs/D_obs` numerator/denominator and UNKNOWN rules remain fully mandatory **within the OBSERVED subset**.
- **Separate INFERRED lane**: actual GitHub Issue/PR/diff/Task Learning/operation records may be interpreted as a **hypothesized Pivot/Revisit**, with `classifier_or_labeler_revision`, evidence/source refs, cohort and capture window, comparison/equivalence hypothesis, causal ordering, privacy classification, counterevidence and UNKNOWN coverage. Public native existence is OBSERVED **as a record**, but a strategy inference is **INFERRED**. `SELF_REPORTED` intent stays separately labeled; no auto-upgrade. Only classify if actual supported inputs and source-order/coverage permit; unknown inputs do not become negative labeled cases.
- **Two independent opportunity denominators**: `N_obs_pivot/D_obs_pivot` & `N_obs_revisit/D_obs_revisit` report independently *qualified real strategy* behavior; `N_inf_pivot/D_inf_pivot` & `N_inf_revisit/D_inf_revisit` report only *classifier labeled behavior among observable eligible events of one declared revision/cohort*. Do not pool/compare rates or use inferred labels to prove effectiveness, improvement, Task PASS, accepted Strategy selection, or an actual Revisit. Where no real public source exists, `UNKNOWN/NOT_COMPARABLE` is truthful and allowed, not a reason to mint a provider capture contract.
- **Positive**: owner-approved strategy X→Y→equivalent X′ with native causal lineage yields qualified observed Pivot/Revisit; separate valid GitHub PR lineage without goal owner may produce an *explicitly inferred* diagnostic if qualified for labeler, not an observed Pivot. **Forbidden**: diff or self-report implies strategy despite owner contradiction; classifier revision absent; duplicate/parallel/missing intermediate synthesized into fake order; failed rollback counted as verified Revisit; ungraded/self-contradictory/denied-publication/not-yet-adopted v5 silently counted or published.
- **Product release boundary**: this is optional ADS Level 3 analysis interpretation at current owner `GITHUB_AGENT_INTERACTION_PROTOCOL.md` §10, not a new report family, mandatory agent tracer, required Tool, public v5 schema extension, Tally decision state or trained labeler. No claim that task-meta v0.2 or Tally already supplies actual samples.
