## 2. Logical data contract — strict conceptual identity and evidence

Normative semantics belong in the existing §10 owner, with a focused reusable behavior reference; **the following logical records do not automatically become separate ADS JSON Schemas or new `ai-dev:event` types.** Projects implement private records as needed and preserve source identities; any public projection is governed by §4.

| Type | Mandatory semantic fields before a **comparable** conclusion | Not allowed |
| --- | --- | --- |
| `ObservedOperation` | source namespace/event ID and revision, physical/logical Attempt/ref, adapter+mapping revision, `observed_at` clock domain, evidence class and coverage; declared Task/Dispatch correlation if actually accepted | no source-less observed facts; a tool call or planned step is not a selected Version |
| `StrategyCandidateRef` | owner scope, source-qualified stable candidate/version fingerprint, candidate-lineage or equivalence evidence, applicable constraint/technique/verifier objective revision; unknown alias remains distinct | Agent narrative/branch label/model guess alone is not equivalence |
| `VersionState` | `state_id` scoped by owner+Task/Attempt and a source-qualified immutable **selected** source/tree/ChangeSet fingerprint; `candidate_ref` plus selection event/ref, applicable baseline, observed/unknown eligibility and currentness | not 1 git commit = 1 version; unselected working tree/declared plan cannot become selected state |
| `Transition` | `transition_id`, `before_state_ref`, `after_state_ref`, source-qualified selection/ordering edge with witness, same comparable Task/subject scope, annotator/classification version, causal/source constraints | GitHub commit timestamp or ingestion order alone is not causality; parallel branches need partial order |
| `VerifierOutcome` | independent actual verifier ref, evaluated exact source/currentness and acceptance scope, pass/fail/skipped/unknown, observed toolchain+window/coverage, benchmark/cohort identity; do not substitute self-report | successful tool result, LLM score or unrelated Task Gate is not acceptance proof |

**Identification:** stable object IDs may use a project-defined qualified opaque string but MUST bind original source namespace and immutable source revision/digest; content hash equality without candidate selection is insufficient. When a chosen VersionState cannot be reconstructed from original material, outcome is `UNRESOLVED`; do not back-assign future commit SHA to previous dirty execution. Changed source revisions generate new source-bound facts, not silent rewrite. Native GitHub ref values and SHA aliases must be resolved to full immutable values before acting as evidence. Exact hash/tree equivalence is not *strategic* equivalence by itself.

### 2.1 Annotation and disagreement

- Per **claim** `evidence_class` is `OBSERVED|SELF_REPORTED|INFERRED|UNKNOWN` (existing §10 vocabulary). Behavioral intent is at best source-bound self-report or inference unless an independent external artifact/decision concretely establishes the **external** selection fact; no instrumented read of private thought is required or permissible.
- Optional labels `action_category`, `intent_label`, `pivot_flag`, `revisit_flag` are **annotations**, not authoritative workflow state or Gate. Retain classifier/annotation schema revision, emitter (human/model/rule), method version, raw evidence refs, contradictory classifications and review/adjudication state. A decimal confidence is **not** an objective probability unless an actual calibration source/cohort is qualified; absence ⇒ `UNKNOWN`.
- Two annotators can disagree about a transition with identical raw source; preserve both signed/source refs and `DISPUTED/UNKNOWN` resolution (do not majority-vote into accepted Pivot). Source-owner override must cite the actual authority/independent evidence and immutable new revision; old labels remain as historical evidence.
- Partial capture, hidden candidates or unknown intermediate versions cannot create a confident `NO_PIVOT` or `NO_REVISIT`; absence of evidence is not zero.

## 3. Pivot, Revisit and explicit counterexamples

**Pivot (supported):** a source-witnessed transition between distinct qualified `VersionState` selections which changes a **material strategy dimension** (technical approach, verification method or actual governing constraint) and has (a) real before/after candidate identities, (b) observable selection/commit/decision evidence, (c) non-inferred method/label version and (d) no counter-evidence classifying it as mere retry, rollback, failure recovery or local parameter/code polish. A Pivot label based solely on Agent self-report is `SELF_REPORTED/UNKNOWN`, not established as `OBSERVED`.

**Revisit (supported):** for states A→B→A′, (1) A/B/A′ selected and causally ordered within the qualified scope, (2) A and A′ have a **source-qualified original candidate/strategic equivalence relation** (exact snapshot equivalence alone is insufficient), (3) B shows real nontrivial departure from candidate A, (4) A′ is **new re-selection** of historically visited candidate after B (not replay/rollback/recovery mechanism), and (5) the relevant intermediate records are complete enough to rule out spurious neighboring/parallel order. Revisit can be labelled UNKNOWN even when all three source snapshots are readable but the selection/intent lineage is missing.

**Counterexamples MUST not be counted:** identical tool command delivered twice; two physical retries under one strategy; restoring failed machine state or recovering lost ACK; automatic git rollback of a bad edit; a commit with same diff but no explicit candidate selection; branch merge where parents are concurrent without verified order; source timestamp order without common clock; annotator disagreement without adjudication; incomplete trace with missing state B. `ROLLBACK/RECOVERY/LOCAL_REVISION/UNRESOLVED` are **interpretation classes**, not new `state:*` or GitHub Gate status.

### 4.1.1 Canonical population, identity and dedup (R1 P1-01 normative repair)

**Counting domain.** A public behavioral numeric claim is scoped to exactly one source-qualified `(repository,Task,Attempt,original-selected-trace-scope,definition_revision,annotation_revision,cohort_revision,verifier_scope,observation_window)`, with a declared clock, sampling/coverage mode and eligible set. Its **base unit is one unique source-qualified, causally ordered `Transition` edge** (selected before/after VersionStates), **never** one commit, VersionState, operation, delivery, retry, provider record, report revision, Task, or free-text strategy name. A `Revisit` uses a distinct unit: **one unique source-qualified *re-selection event* of a selected VersionState** after sufficient observed candidate history. Public positive counts and denominator values are **derived** from qualified original event identities, not arbitrary producer-assigned local counts. T09's typed v5 Schema projection must expose both populations separately; T03 must validate source-based comparability, not treat integers as self-certifying.

**Pivot eligible denominator:** `eligible_pivot_transitions` is the number of distinct source-qualified Transition edges with (a) immutable selected before/after identities and witnessed causal order, (b) original candidate/effective strategy/verification/constraint evidence sufficient to classify a material change **or a witnessed non-material change**, (c) qualified compatible task/cohort/clock/verifier window and (d) a resolved **OBSERVED** material-change annotation under the pinned ADS behavior-definition semantics. `pivot_count` counts only the eligible edges with a **source-supported material strategy change**. A same-strategy repair classified as a witnessed negative contributes to the eligible denominator but not the numerator. Retries, duplicate deliveries, mere rollback or recovery, inference-only/self-report-only and disputed classifications are **excluded** from eligible numerators and denominators, not reinterpreted as observed negatives. `observed_transition_units` separately records the deduplicated Transition source edges seen within the bounded window regardless of eligibility. `excluded_unknown_transition_units` counts deduplicated edges that cannot be classified; `disputed_classification_units` records those with contradictory annotations, without double counting either as eligible. An unknown unobserved population means `coverage=PARTIAL|UNKNOWN`, not `COMPLETE`.

**Revisit eligible denominator:** `eligible_revisit_opportunities` is the number of distinct **selected re-selection events** whose *own preceding selected-state history* contains at least two causally ordered, source-qualified prior selected states in the same scoped candidate/Task/Attempt lineage and has enough complete historical candidate identities/equivalence and intervening selection to decide **return vs non-return**. The event is eligible whether it returns to an earlier comparable candidate or selects a demonstrably different candidate after that history. `revisit_count` counts eligible re-selection events with (a) same source-qualified prior candidate/strategic equivalence, (b) at least one **real, source-qualified, nontrivial intervening departure**, (c) witnessed **new deliberate selection** distinct from mere rollback/retry/recovery and (d) complete ordering/source evidence. The first selection and the immediate next selection are **not** eligible Revisit opportunities; a third selection may be eligible if the earlier history is complete. `observed_reselection_units` records all distinct selection events seen, while `excluded_unknown_reselection_units` records unclassified candidate return/opportunities. A claim of `NO_REVISIT` requires a complete observed eligible set; unknown previous selections, parallel branches or disputed labels make the affected comparison UNKNOWN.

**Canonical dedup identity:** a qualified Transition key is `(original owning source namespace, Task/Attempt/trace selection scope, source-owned original causal selection-event ID, immutable before_state identity, immutable after_state identity)`; a Revisit key is the original **after-state selection event ID and selected VersionState identity**, not the repeated older candidate or a current reporter's `transition_id`. Report/publication revision, delivery attempt, OTel span delivery, annotation revision and source-event correction revision **must not** appear in the stable uniqueness key. They belong to a separately witnessed append-only `source_revision + predecessor_digest` chain. Same canonical identity + same source revision/digest is one event; conflicting digest/effect/selection for that identity and revision ⇒ `CONFLICT`, no latest timestamp preference; later source revision changes provenance/classification **of the same unit**, not the number of units. Missing predecessor pages, source-owner alias authority or source material ⇒ `UNKNOWN/NOT_COMPARABLE`. Distinct publisher IDs sharing apparent local IDs cannot be merged without independent source-qualified original-event alias equivalence. Counting the same real event once in each publisher's reports is **not** permission to sum both report totals.

**Label inclusion & compare rule:** counted numerator units require *source-qualified OBSERVED selection/classification evidence* under the pinned common ADS behavior-definition semantics; `SELF_REPORTED`, `INFERRED`, `UNKNOWN`, absent, uncalibrated or disputed labels may be published **only as separate qualified observations/exclusions**, never silently promoted into verified Pivot/Revisit counts. Independent adjudication may later create a **new immutable correction revision** with its own authority, retaining historical disagreement and lineage. For headline **rates or comparisons**, source-qualified `coverage=COMPLETE`, no unclassified eligible population, compatible declared sampling/selection policy, full original event and independent verifier windows, `observed_transition_units` and `observed_reselection_units` plus both separate eligible denominators and exclusion receipts **must** be attested; `PARTIAL|UNKNOWN`, missing/disputed labels capable of shifting the eligible denominator, or insufficient comparable clock/budget/cohort ⇒ `UNKNOWN/NOT_COMPARABLE`, not a best-effort percentage. Raw counts MAY remain bounded factual with explicit incomplete qualifications but cannot masquerade as comparable rate or observed zero. Enforce `0 <= pivot_count <= eligible_pivot_transitions`, `0 <= revisit_count <= eligible_revisit_opportunities`, and `eligible_* <= observed_*` where populations are complete. An eligible denominator of zero yields **undefined rate / NOT_COMPARABLE**, never 0% or 100%. Two compared reports require matching **normative count-unit semantic definition and effective selection/annotation ontology version**, original-event equivalence/coverage, task/cohort/verifier and allowed source privacy. An opaque `definition_revision` string is merely a locator until the actual immutable **definition specification + source digest** is resolved and semantics equal; different or unresolvable revisions require `NOT_COMPARABLE`, even when both reports satisfy JSON Schema. T09 must pin this semantic definition in its typed public projection; do **not** create a second authority or unreviewed histogram vocabulary.

**One-source A→B→A′ deterministic oracle:** original qualified selections S1(A), S2(B), S3(A′), edges E12 and E23, with source-observed material strategy shifts on both edges and **verified** A/A′ candidate lineage separated by B. The exact deduplicated **Pivot** eligible set is `{E12,E23}`: `observed_transition_units=2`, `eligible_pivot_transitions=2`, `pivot_count=2`. The **Revisit** eligible set is `{S3}` alone (first S1 and S2 ineligible): `observed_reselection_units=3`, `eligible_revisit_opportunities=1`, `revisit_count=1`. A delivery retry of E23 and a source revision E23@r2 (same original event identity, valid predecessor chain) change **neither** denominator nor numerator. Producer A and producer B observing this same source with verifiably matching source mapping MUST emit these **same counts**, or the disagreement is `CONFLICT/NOT_COMPARABLE`; producer B's attempted "3 VersionStates ⇒ pivot denominator=3" or "one distinct strategy family ⇒ pivot_count=1" is **invalid under this definition**, even if all integers are nonnegative. A disputed E23 material-change annotation gives `disputed_classification_units=1`, reduces the eligible Pivot count for that source-qualified snapshot to 1, and **forbids** a comparable complete-rate claim until genuinely adjudicated; its Revisit claim is likewise `UNKNOWN` if the disputed evidence affects the necessary departure/return. A self-reported intent cannot fill that gap. `B08/B10/B11` must test both producer differences, duplicate deliveries/source revisions, denominator-zero, disputed/self-reported exclusions and explicit `NOT_COMPARABLE/UNKNOWN`.

**Compatibility authority check (critical):** currently v5 only exists in `version/v4.16` source and is not yet adopted as immutable main v4.16. Adding an **optional** typed member to the same future Report-v5 Schema MAY qualify as a pre-adoption minor source addition, but cannot silently change validity of existing positive v5 instances, or cause a v5-old pinned reader to accept unrecognized keys. A v5-old reader seeing a post-R7 v5-new report must reject it as `UNSUPPORTED` under its effective source/schema pin and leave population coverage `UNKNOWN`; a new reader may parse both old-v5 and new-v5 using the actual immutable producer pin/protocol, rather than treating missing new field as observed zero. If actual adopted v5 instance/source exists outside qualified pre-adoption tests, **STOP and escalate** for an explicitly versioned successor: no in-place contract change after qualified adoption. This requires independent L2 approval even though the member is optional.
