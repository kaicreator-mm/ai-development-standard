## 1. R3 independent P1-02 — null-source summary, correction, privacy and late evidence

The only proposed source-null publication is **v5 `EXECUTION_SUMMARY` with `attempt_binding=COLLECTOR_ONLY`**, `source_status=UNPINNED|UNKNOWN`, `source_sha=null`, reason, source-qualified collector observation refs, `source_currentness=UNKNOWN`, and `verifier` explicitly `NOT_RUN|UNKNOWN` with no false `subject_sha` or success. Under a strict v5 schema, source-null `CANONICAL_DISPATCH`, `currentness=CURRENT`, any verified `PASS`, an unqualified public source, or feedback/correction source-null are invalid. Publication is optional and requires clearance in §3; Option A (hold/nonpublication with explicit missing-evidence status) remains the fallback where authority/clearance is unavailable.

**Two independent subjects (not the same field):**
- `notice_publisher_source_sha` / `ads_revision` are the **current immutable source of the legitimate correction publisher / protocol**, never a substitute for the original dirty Attempt's unavailable bytes.
- `target` binds *historical observed report* identity: native GitHub owner repo/Issue/comment URL+ID, original `ads_profile=ads/github/v5:report`, publisher_namespace, task_ref, attempt_ref, report_id, original revision, and exact original **data-only digest**. `target_source_status=UNPINNED` and `target_source_sha=null` are allowed as **typed target description only**, not as the correction publisher's source.

**Allowed immutable lineage (no edit/update of the original comment):**
1. A qualified original publisher with actual GitHub permission and matching owning logical namespace posts an **independent v5 `EXECUTION_CORRECTION` notice** for the unpinned summary. That notice's *own* publisher/source pin is non-null, it carries typed `REVOKE|REDACT|DISPUTE`, source-authorized reason and the target identity tuple above. Read back the actual native target and notice comments. Cross-Issue/Task/Attempt/namespace, wrong profile/digest/comment or insufficient original-publisher authority => `UNVERIFIED/DISPUTED`, no target mutation, irrespective of transport GitHub login.
2. Privacy-driven REDACT/REVOKE may remove or minimize a leaked GitHub comment only by the authorized owner; publish a sanitized tombstone that keeps exact target identity/digest where safe, never sensitive content. If target becomes inaccessible/edited, record `UNKNOWN/DISPUTED` and observed deletion/edit history; no fabricated remote completeness.
3. If an immutable source **artifact covering the actual original execution bytes** is later independently witnessed, publish a **new v5 summary revision** of the same report_id + original Attempt with an explicit `source_association` evidence ref, exact original-material digest/provenance and actual source SHA *only if those bytes match*. The original source-null version remains immutable historical collector observation. Even a valid later association **cannot** change `COLLECTOR_ONLY` into `CANONICAL_DISPATCH`, cannot retroactively produce an accepted Claim/current Task/Review/Gate or fake a verifier. A merely later commit with similar code does NOT qualify the earlier dirty Attempt; leave source UNKNOWN.
4. A correction notice and a later source-associated revision are **distinct** facts. Their order cannot erase a witnessed prior correction; consumers reconcile versioned target identity, read-completeness and current publication authority. Ambiguity => `CONFLICT/INSUFFICIENT_EVIDENCE`, not latest timestamp wins. Different publishers cannot silently edit/revoke another namespace's report; delegated owners need source-qualified existing authority.

**Protocol/schema decision still requiring L2 review:** bind the current publisher pin in the common v5 subject/actor *independently* from the original observed Attempt source, so feedback and correction remain fully current while the target may be UNPINNED. Reuse existing public data digest, correction, native ownership and Task/Attempt lineage; do not create a second Task Claim or new Event family.

## 2. R3 independent P1-03 — deterministic physical usage, revisions and financial dedupe

**Typed public normalized projection (bounded, not a complete private Trace):**

- `scope_identity`: canonical repo, task_ref, attempt_ref, publisher_namespace, adapter_id/version, original provider run/ref when witnessed; do not use the shared GitHub transport login as publisher identity. An `observation_id` is **namespaced by this scope**, source-owning producer identity and mapping revision, not merely a local integer.
- `logical_call_ref` and `physical_attempt_ref` distinguish one logical request from each actual retry. The **physical key** is `(publisher_namespace, task_ref, attempt_ref, adapter_id, provider_run_ref, physical_attempt_ref)` with source receipt/currentness; a bare '1' in two Attempts never collides. If provider_run_ref or source alias ownership cannot be verified, those physical events cannot be silently equated across publishers/adapters; retain `UNKNOWN/NOT_COMPARABLE`.
- The **measurement identity** is physical key + `metric_id` (versioned metric registry), canonical unit, `measurement_kind` (e.g. counter delta / cumulative snapshot), `window_id` (bounded source-qualified interval, coherent clock and unit), plus source-event identity. Each source-event revision is immutable source evidence; the reducer groups by stable original observation identity and reconciles non-overlapping deltas or qualified latest *cumulative watermark*, **not all deliveries, retries or revisions added together**.
- Distinguish `report identity = (owning Issue,publisher_namespace,report_id,revision,report_kind)` from **metric identity**. First deduplicate duplicate native comments of the same identity+digest; identity with differing digest => `CONFLICT` (no latest-wins); verify full predecessor revision chain/read scope/native edit/currentness; choose one qualified current representation per report_id where determinable. Then deduplicate source observations across reports using qualified physical+metric/window identities, not report count. A revision with the same actual provider event **updates observation provenance**, not its measured usage amount.
- Two providers or adapters claiming one physical event require explicit **source-qualified alias equivalence** or reconciliation owned by the publisher; do not merge on model name/time window similarity. If equivalence/conflicting cumulative vs delta semantics is unresolved, the affected sum/comparison is `UNKNOWN/NOT_COMPARABLE`, even if all metrics individually schema-valid.
- Cache/reasoning subsets are non-additive to inclusive totals, unless the authoritative provider definition explicitly excludes them. Parent spans, overlapping intervals, physical retries, logical calls, validation/rework costs remain different measures. Different clocks/unresolved time source => no wall-time sum/union claim; compatible grounded same-clock intervals MAY use interval union.

**Multiple cost observations with explicit accounting identity**: `(owning publisher, economic_scope_ref, invoice_or_provider_receipt_ref, currency, cost_category, billing_window, source_revision)`, where the stable accounting identity **excludes** transport duplicate and public Report revision. BILLED, PROVIDER_REPORTED and ESTIMATED are separate bases; a provider quote and a billed invoice covering the same calls/window are **overlapping alternatives**, never 2 addends. For actual bill total, source-qualified disjoint invoice scopes and non-overlapping billing windows are required; absent settlement IDs or complete bill coverage => billed total UNKNOWN, not 0 and not ESTIMATED. Multiple-currency totals remain NOT_COMPARABLE absent a source-qualified accepted currency conversion rule. A later invoice revising a prior receipt must explicitly supersede its accounting identity; without source-backed precedence or unique receipt scope, CONFLICT. No summing both attempt-level and task-level cost snapshots.

**Completeness receipts:** model/call/cost conclusions state actual observed attempted population, watermark/window, missing events, duplicate/conflict refs, excluded retry and provider populations, and publication/readback completeness. Partial provider stream or missing 403/429 page or late/edited native comment => UNKNOWN at precisely affected scope; unaffected independent observations may still be usable. Publish aggregate only when source class authorizes and public sample volume is bounded; otherwise retain private source and publish appropriate absence/limits.
