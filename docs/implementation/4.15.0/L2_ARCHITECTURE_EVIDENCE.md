## B. Architectural invariants

1. One fixed first-line `<!-- ads:github -->`, one fenced YAML mapping of **exactly** `schema`, `kind`, `data`; no KEY=VALUE or Markdown-as-machine alternate path. The v4.15 **per-kind currentness matrix** retains **v3 `work_item/intent/event` as current executable**, while **new reports only** use `ads/github/v4`; v3 Reports are read as historical by v4.15 readers. v4.14 original root/source remains unchanged.
2. Only `kind: report` gains v4 typed execution/feedback semantics; Work Item, Intent and Event **stay in the existing v3 validated root with its original pinned offline `$ref` registry**, not cloned into a second schema or Python-only validator. Narrow Protocol §16.4 `latest-only` prospectively to per-kind/current-effective-pin semantics, with mixed-pin tests.
3. A report is an **observation with source**. `SHAPE_VALID_ONLY` cannot become Task PASS, authorized Claim, Gate/Review verdict, Provider remote completion, DomainHarness K effect, or a transferable Package credential.
4. `EXECUTION_SUMMARY` is task-meta-published from observed/private immutable evidence; `EXPERIENCE_USE_FEEDBACK` is Tally-published from GitHub native facts and its **own** action evidence, without any private task-meta manifest.
5. GitHub-only means Tally's *entire* relevant input dependency is GitHub; no direct task-meta API/store/SDK/object/Manifest/Trace. Live credential scopes and absence/denial of private egress must be witnessed, not asserted.
6. Published data is bounded and redacted. Both writers and GitHub-only Tally compute `SHA256(RFC8785_JCS(validated_data))` as a **derived external/receipt comparator**; native GitHub `updated_at/created_at` or GraphQL edit flags and changed per-comment digests cause `UNVERIFIED/CONFLICT`, without requiring a private publisher receipt or claim of perfect immutability. A correction only invalidates within its owning Issue/report namespace, not across logical publishers sharing one GitHub login. Late validated evidence/learning => new immutable source-manifest-backed summary revision. Missing billed cost, independent verifier or experience suitability remains UNKNOWN/INSUFFICIENT_EVIDENCE.
7. Full ADS v4.15 Release Qualification requires actual producer + actual consumer code on real GitHub. A static demo/schema test alone **cannot** replace the external E2E Product requirement.
8. Immutable code/ADS/Task candidate under test is separate from effective consumer adoption. During pre-RQ compatibility E2E, isolate the *frozen candidate* as test subject in a bounded smoke project; never change production project-local pin or active accepted Claim.
